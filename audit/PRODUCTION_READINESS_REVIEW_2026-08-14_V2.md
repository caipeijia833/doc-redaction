# 上线准备度代码复审 V2

复审日期：2026-08-14
版本：`0.1.0-poc`
目标：单机、离线、Windows x64 正式版优先；macOS 13+ 双架构后续验收
结论：**可作为受控单机试点候选包，不批准直接作为正式生产版发布。**

## 1. 结论依据

正式上线至少需要同时满足四个条件：程序在声明范围内正确运行、敏感数据不会因失败路径泄露、发布物可验证且可恢复、目标机器和真实业务数据完成验收。当前版本已经具备前三项的主要基础，但最后一项仍缺真实金标语料、macOS 实机、签名密钥和独立安全验证。因此“代码可以运行”和“允许正式上线”不能画等号。

与 V1 相比，本轮已消除官方 OpenCV 供应链、Windows 工作进程失控、发布包本机启动、离线漏洞门禁、升级回滚框架等一批代码侧阻断项。剩余阻断项中，一部分必须由项目所有者提供机器、证书、密钥、数据或验收标准；另一部分仍可继续由开发侧实现。

### 2.2 Windows 进程树资源约束

- 正式 Windows 包强制把一次性工作进程加入 Job Object，启用 kill-on-close、活动进程上限 32、单进程和整个进程树的提交内存上限。
- 不同机器档位使用 2 GiB、3.5 GiB 或 4 GiB 提交内存上限；并发默认 1，防止多个本地多模态模型实例挤爆内存。
- 任务历史记录是否成功应用 Job Object、提交内存上限、进程树/单进程峰值提交内存、任务目录基线/峰值/新增磁盘量。
- 工作进程的 Java 临时目录位于任务目录内并在结束后清理。
- 边界声明：Job Object 只限制生命周期和资源，**不限制工作进程读取当前用户可访问的其他文件，也不阻断其网络权限**；不能将其表述为 AppContainer、低权限账户或完整沙箱。

### 2.4 视觉、OFD 和升级能力

- 相邻采样帧中，种类、规则和值兼容且位置接近的视觉命中，会生成保守的中间遮挡桥；已经取消把所有命中合并成单个巨型静态矩形的处理。
- 仍无法检测“完全出现在两次采样之间又消失”的短暂敏感画面，不能声称已实现逐帧完整跟踪。
- OFD 工作协议升级为 V2，按每页实际像素和渲染密度保留独立物理宽高，不再强制所有页面为 A4 宽度；已通过合成 100 mm × 50 mm 页面往返渲染测试。
- 离线升级清单采用 Ed25519 签名，并验证可信公钥 ID、完整文件集合、路径白名单、逐文件大小和 SHA-256、数据架构版本；拒绝符号链接和 `data` 路径。
- 升级期间用单实例锁阻止运行中替换；旧程序树先备份再切换，回滚不会替换 `data`。端到端临时密钥测试已完成签名、验证、0.2.0 应用、数据哨兵保持、回滚 0.1.0、数据哨兵再次保持。
- 正式可信公钥模板故意为空，因此当前包会拒绝一切真实升级；这是安全默认值，不是可直接发布的密钥配置。

## 4. macOS 明早验收顺序

1. 确认虚拟机 CPU 架构；只准备与该架构一致的 JRE、Tesseract、FFmpeg/FFprobe、whisper.cpp、OpenCV 4.13 JNI、llama.cpp 和模型。
2. 用 `packaging/package-macos.sh` 生成该架构包；脚本会用 `file` 拒绝混合架构原生文件。
3. 在完全断网环境运行包内 `preflight-macos.sh`。
4. 执行 `audit/macos-acceptance.sh <包目录>`；保留 `data/diagnostics/macos-acceptance/` 全部证据。
5. 开发测试包先不设置 `DOC_REDACTION_REQUIRE_SIGNED=1`；具备 Developer ID 签名和公证票据后再设置为 1 重跑。
6. 把失败日志和架构信息交回开发侧。不得用 Rosetta 成功替代原生同架构通过，也不得用一个架构的结果代表另一个架构。

## 5. 上线判定

- **当前允许**：隔离机器、非生产原件、人工复核、可随时清除数据的受控单机试点。
- **当前不允许**：无人复核处理真实唯一原件、面向多人/网络开放、承诺全格式无损、承诺零漏脱敏、把还原密钥与密文同机无治理保存、对外标记为正式生产版。
- **升级为正式候选的最低门槛**：P0 真实金标通过；目标 Windows/macOS 架构验收通过；签名/公证/发布公钥就绪；权限沙箱或经书面接受的等价部署隔离；独立安全测试无未处置高危问题；备份和还原演练通过。
